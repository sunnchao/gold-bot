### 3. **挂单逻辑增强** ⭐⭐⭐

**问题描述**:  
重复挂单检查只匹配方向，不检查价格，导致多个不同价格的挂单被误判为重复。

**修复内容**:
```mql4
// 修复前（行 1415-1432）：
if((newIsBuy && isBuyPending) || (!newIsBuy && isSellPending))
{
   Print("❌ 已有相同方向挂单：", brokerSymbol);
   ReportResult(cmd_id, "ERROR", 0, "duplicate_pending");
   return;
}

// 修复后：
if((newIsBuy && isBuyPending) || (!newIsBuy && isSellPending))
{
   // 检查价格是否过于接近（10 点以内视为重复）
   double existingPrice = OrderOpenPrice();
   double point = GetSymbolPoint(brokerSymbol);
   if(MathAbs(existingPrice - entry) < 10 * point)
   {
      Print("❌ 已有相近价格挂单：", brokerSymbol, " 现有=", existingPrice, " 新=", entry);
      ReportResult(cmd_id, "ERROR", 0, "duplicate_pending");
      return;
   }
}
```

**效果**:
- 允许多个不同价格的挂单（如分批建仓）
- 避免 10 点以内的重复挂单

### 4. **JSON 解析增强** ⭐⭐⭐⭐

**问题描述**:  
原始 JSON 解析函数无法处理：
- 转义字符（`\"`、`\\`、`\n` 等）
- 字符串内的特殊字符（如方括号、引号）

**修复内容**:
新增两个安全函数：
- `GetJsonStringSafe()` - 处理转义字符的字符串解析
- `GetJsonArraySafe()` - 忽略字符串内括号的数组解析

**替换范围**:
- `PollAndExecute()` - 指令轮询
- `ExecuteOpen()` - 价差开仓
- `ExecuteClosePartial()` - 价差部分平仓
- `ExecuteCloseAll()` - 价差全部平仓
- `ExecuteSignal()` - 信号执行
- `ExecutePending()` - 挂单执行
- `ExecuteCancelPending()` - 取消挂单
- `ExecuteClose()` - 平仓
- `CheckForUpdate()` - 版本检查

**支持的转义字符**:
- `\"` → `"`
- `\\` → `\`
- `\n` → 换行
- `\t` → Tab
- `\r` → 回车

**兼容性**:
- 原有函数 `GetJsonString()` 和 `GetJsonArray()` 保留（未被调用）
- 所有调用已替换为安全版本

## 📝 已知限制

1. **JSON 解析仍不支持**：
   - 嵌套对象/数组（深度 >2 层）
   - Unicode 转义（`\uXXXX`）
   - 科学计数法负指数（`1e-5`）

2. **挂单价格检查**：
   - 10 点阈值为硬编码，不适配所有品种
   - 建议后续改为 `MinStopLevel * 2`

3. **HTTP 重试策略**：
   - 仅重试 1 次，间隔 500ms
   - 某些网络环境可能需要更长延迟
